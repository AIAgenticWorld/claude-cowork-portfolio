# n8n Workflow Automation — Patterns Reference

This skill documents the patterns used to connect Claude Cowork to n8n workflows. It
covers the trigger types, payload formats, polling patterns, response extraction paths,
error handling, and data safety rules that apply across all n8n-integrated Claude skills.

---

## Core Concepts

### Trigger Types

n8n workflows can be triggered in different ways. The trigger type determines the payload
shape Claude must send. Using the wrong type is the most common cause of failures.

| Trigger | When to Use | Payload Shape |
|---|---|---|
| `form` | Workflow starts with a Form node | `inputs.type = "form"`, data goes in `inputs.formData` |
| `chat` | Workflow starts with a Chat Trigger node | `inputs.type = "chat"`, data goes in `inputs.chatInput` as a JSON **string** |
| `webhook` | Workflow starts with a Webhook node | `inputs.type = "webhook"`, data goes in `inputs.body` |

The trigger type is set in the `inputs` object, not as a separate parameter.

### Execution Modes

Always use `executionMode: "production"`. The `"test"` mode uses pinned data and does
not run the real workflow logic.

## Payload Formats

### Form Trigger

```json
{
  "workflowId": "hkSIbx72qd63HyYh",
  "executionMode": "production",
  "inputs": {
    "type": "form",
    "formData": {
      "Field Name": "value",
      "Another Field": "value"
    }
  }
}
```

Field names in `formData` must match the field labels in the n8n Form node exactly,
including capitalisation and spacing.

### Chat Trigger

```json
{
  "workflowId": "DUKNqcvyjpLEV9b5",
  "executionMode": "production",
  "inputs": {
    "type": "chat",
    "chatInput": "{\"action\": \"Generate Message Reply\", \"lead_id\": \"123456\", \"client_message\": \"Full text here\"}"
  }
}
```

The `chatInput` value must be a **JSON string** (note the quotes and escaped inner quotes).
Passing it as a nested object will cause the workflow to fail silently or produce wrong output.

## Polling for Results

Many n8n AI workflows return `status: "waiting"` immediately after the AI Agent finishes.
This is expected — it means the workflow has completed its work and is waiting for further
input. It does NOT mean an error occurred.

**Pattern:**

1. Call `n8n MCP:execute_workflow` and capture the returned execution ID
2. Immediately call `n8n MCP:get_execution` with that execution ID and workflowId
3. Check the result — the output data will be in the execution's `resultData`

```json
{
  "executionId": "<id from step 1>",
  "workflowId": "<same workflow id>"
}
```

Do not wait between the execute call and the get_execution call. The workflow runs
synchronously from Claude's perspective — by the time `execute_workflow` returns, the
work is done.

## Response Data Extraction

n8n wraps output in a deep nested structure. The exact path depends on which node
produced the output.

### CRM Creation Workflow — Extract Lead ID

After calling the ClientJoy creation workflow, extract the Lead ID from:

```
data.resultData.runData["HTTP Request"][0].data.main[0][0].json.data.id
```

If this path does not exist, the workflow likely failed. Check:
```
data.resultData.runData["HTTP Request"][0].data.main[0][0].json.error
```

### AI Agent Workflows — Extract Text Output

For workflows using an AI Agent node (like Supervisor_Sales):

```
data.resultData.runData["AI Agent"][0].data.main[0][0].json.output
```

The `output` field contains the full text generated by the AI Agent, which may include
multiple versions separated by headers or line breaks.

### General Pattern

The n8n result structure follows this shape:

```
data.resultData.runData["[Node Name]"][0].data.main[0][0].json.[field]
```

Where `[Node Name]` is the exact name of the node in the workflow editor (case-sensitive,
including spaces).

## Error Handling

### "Cannot read properties of undefined"

This almost always means a payload format issue. Check:
- Is the trigger type correct? (form vs chat vs webhook)
- Is `chatInput` a JSON string, not a nested object?
- Are field names in `formData` exactly matching the Form node labels?

### Workflow Returns Empty Output

If the AI Agent path returns nothing:
- Check if the workflow actually reached the AI Agent node (look at other nodes in `runData`)
- Check if `chatInput` was parsed correctly on the n8n side

### Timeout on First Call

Some AI workflows (especially those with sub-workflows or long prompts) can take 30-50
seconds. If the first call times out:
1. Retry once with the identical payload
2. If it times out again, fall back to manual processing and flag this in the summary

Do not change the payload on retry — the timeout is a latency issue, not a format issue.

## Google Sheets Field Safety

Several workflows log output to Google Sheets via n8n. Sheets interprets certain
starting characters as formula syntax, which corrupts the cell value.

**Never start a logged field value with:**
- `=` (formula trigger)
- `+` (implicit formula)
- `-` (implicit formula)
- `@` (function trigger)
- `|` (table syntax in some versions)

**Fix:** prefix the value with a space, or rephrase so the line doesn't start with
these characters.

This most commonly affects:
- Email bodies that start with a dash (e.g. bullet points)
- URLs logged directly (if preceded by `=`)
- Code snippets or JSON logged into Sheets

## A Complete Example: Supervisor_Sales Round-Trip

### Step 1 — Trigger

```json
Tool: n8n MCP:execute_workflow
{
  "workflowId": "DUKNqcvyjpLEV9b5",
  "executionMode": "production",
  "inputs": {
    "type": "chat",
    "chatInput": "{\"action\": \"Generate Message Reply\", \"lead_id\": \"1257026\", \"client_message\": \"Hi, I saw your profile and I'm interested in SEO for my e-commerce store. We're doing about 50k/month in revenue and struggling to grow organic traffic.\"}"
  }
}
```

Returns: `{ "executionId": "abc123", "status": "running" }`

### Step 2 — Poll for Result

```json
Tool: n8n MCP:get_execution
{
  "executionId": "abc123",
  "workflowId": "DUKNqcvyjpLEV9b5"
}
```

### Step 3 — Extract Output

```javascript
const output = data.resultData.runData["AI Agent"][0].data.main[0][0].json.output;
```

The `output` string will contain the full reply and a shorter version. Parse as plain
text — there is no structured JSON inside `output`.

## Building New Skills with n8n

When adding a new n8n-powered workflow to a Claude Cowork skill:

1. Confirm the trigger type by looking at the first node in the n8n workflow editor
2. Test the payload manually via `execute_workflow` before writing the skill
3. Map the exact response extraction path by inspecting a successful execution in the n8n editor
4. Document the workflow ID and trigger type in the skill's `docs/setup.md`
5. Add a retry instruction for timeout handling
6. Add a Google Sheets safety note if the workflow logs to Sheets
